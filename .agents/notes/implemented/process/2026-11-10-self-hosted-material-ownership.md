# Agent Note: 自管理时的分发源与项目副本归属

Status: implemented

## Problem

技能需要把维护材料复制到其他项目，而本仓库也使用同一份技能管理自身。分发源和根目录维护副本如果各自编辑，项目检查可能使用一套规则，用户安装后却获得另一套规则。

## Decision

`agent-docs/assets/project/` 拥有可分发材料；根目录 `.agents/` 对应文件是本仓库使用的消费者副本。维护先修改源，再检查并同步受影响副本。项目级检查器比较这部分文件的字节内容，同时检查分发 Markdown 引用。项目特有路径、中文文档及维护要求分别留在配置、docs 和根指令，不写入通用材料。

## Alternatives considered

**直接引用全局安装目录。** 全局目录依赖机器和安装状态，无法保证克隆仓库后规则仍然可用，也无法实际覆盖复制后当轮加载的路径。

**仅维护根目录副本。** 用户安装的分发包可能保持旧内容，无法约束消费者与发布内容的一致性。

**使用符号链接消除副本。** 初始化工具会拒绝通过符号链接写入共享位置；实际文件副本保留了目标项目独立维护的使用方式，也能让本仓库验证真实消费路径。

## Consequences

仓库保留两份相同材料，但通过单一所有者和确定性检查控制漂移。同步需要一次明确的维护动作；该一致性要求只适用于技能自身的仓库，不禁止其他采用该技能的项目适配自己的规则。

## Verification

[自管理测试](../../../../tests/test_self_management.py) 验证消费者规则被单独修改时检查失败，以及分发引用失效时检查失败。[项目检查器](../../../../scripts/check_project.py) 在日常验证中执行这些约束；文件相同不证明语义正确，内容仍需按照维护工作流复核。
