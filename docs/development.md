# 开发与验证

在仓库根目录使用 Python 3.10 或更新版本开发。运行技能和维护性测试不需要 DSH 仓库、全局技能安装或第三方 Python 包；测试中的归档基线场景需要 Git。

## 修改与同步

先读 [项目指令](../AGENTS.md) 和 [架构与归属](architecture.md)。全局任务路由在 `agent-docs/SKILL.md`；项目工作流和检查器在 `agent-docs/assets/project/`。修改分发材料后，检查根目录对应副本有无独立编辑，再同步受影响文件。不要用反复运行 bootstrap 代替升级，它会保留已有配置和文件。

本仓库的 `.agents/` 副本应与分发材料一致，`scripts/check_project.py` 会拒绝未同步的修改。修改已读取规则后，重新运行对应的激活命令并完整阅读输出；新增必读规则也需要重新激活。四部分的命令和复核格式由 [初始化指南](../agent-docs/references/initialize.md) 维护。

README 描述使用入口；本目录分别维护架构、开发与验收。仅在有长期决策理由时新增 Agent Note。规则正文保留在其所有者中，引用它的文档不再复制完整规则。

## 执行检查

修改完成后，从仓库根目录运行：

```sh
python3 -m unittest discover -s tests -v
python3 scripts/check_project.py
python3 .agents/doc-tools/docs.py check --root .
git diff --check
```

测试会在临时目录创建项目，验证文件冲突、符号链接拒绝、重跑保留、原生 ADR 适配、读取记录要求、归档基线和源副本漂移。临时 Git 提交使用测试专用身份，不修改用户全局 Git 配置。项目检查器发现差异时报告文件位置；先判断正确的所有者再修改，不应为通过检查而无条件覆盖消费者。

如需独立使用基础检查器，可以运行第三条命令。`check` 不需要本机激活记录；初始化验收的 `finish` 需要本轮投递及复核证据，不能把 CI 的结构检查视为 Agent 已经阅读规则。

## 安装与更新

新安装使用 [README 的安装命令](../README.md#安装与使用)。现有全局安装不会随工作目录自动更新：比较安装目录和分发包，备份或保留独立修改，再同步经过验证的文件。项目内测试始终读取仓库分发源，不能证明另一个安装目录与它一致。

## 发布范围

Git 跟踪技能源、项目自身的维护副本、中文文档、决策记录和可移植测试。`forward-tests/`、一次性上游提取脚本、旧本机验收文件及 `.local/` 保留作本地材料，由 [.gitignore](../.gitignore) 排除。分发源直接维护，运行和测试不依赖这些材料。

推送前检查暂存文件与 `git diff --cached --check`，确认许可和来源声明随包保留。发布不应改变现有项目的文档结构或用户配置。
